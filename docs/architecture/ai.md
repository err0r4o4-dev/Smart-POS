# Internal intelligence boundary

Python FastAPI serves live/ready health and an optional development storefront assistant. Health returns strict `{ status: "ok" | "ready", service: string }`, generated X-Request-ID and no-store. Errors use code/message/request_id. Unknown forecast routes return 404; no trained forecast or synthetic prediction exists. Readiness does not depend on the assistant. Docs/OpenAPI HTTP endpoints are disabled; the service has no published port.

## VELO Assistant on local 9Router

The pilot is disabled by default and the Go route cannot be enabled outside a loopback development origin. In the existing ignored environment for an isolated local stack, set `STORE_ASSISTANT_ENABLED=true`, `LLM_PROVIDER=9router`, and `LLM_MODEL=LLM`. Set `LLM_BASE_URL=http://host.docker.internal:20128/v1` when the AI service runs in Docker Desktop and 9Router runs on the host; use `http://localhost:20128/v1` when both run natively on the same host. Native Go also needs `STORE_ASSISTANT_AI_URL=http://127.0.0.1:8001`; Compose sets the internal URL. Give Go and Python the same random `AI_STORE_ASSISTANT_TOKEN` (at least 32 URL-safe characters). Set `LLM_API_KEY` only on the AI service if the router requires it. Do not commit either secret.

The browser sends up to four questions from its current shop session to `POST /api/v1/storefronts/{slug}/assistant`. Go accepts this route only from a direct loopback peer or the configured trusted proxy, then checks origin, rate limit, published shop, and input. A native API listener must bind to a loopback IP. Go forwards only the text to the authenticated internal service. The model receives no catalog snapshot or order data and returns query filters only. Go queries the selected public catalog, excludes unavailable items and supplies the names and exact prices. The browser uses the existing answer flow if the optional service is unavailable; disabling the flag restores the old behavior. Queue, private order tracking, discovery, and merchant guidance do not call the model.

Use synthetic questions for this pilot. A local 9Router can still forward prompts to its configured upstream. The input filter rejects common sensitive patterns but cannot identify all private text. No feedback, training or chat persistence is configured.

Phase 6 target request: authorized organization/branch snapshot with product/base unit, UTC time window, bounded daily demand history, inventory/reorder context, requested method and input schema version. No raw PII, passwords, full database access or arbitrary query capability. Go authenticates/authorizes and bounds snapshots; internal calls need service authentication, request correlation, deadline/retry policy, output validation and idempotent run tracking.

Target response: run_id, schema_version, model_name/model_version, generated_at UTC timestamp, training window, forecast horizon/unit, point estimates and uncertainty where supported, data-quality indicators, explanation metadata and provenance. `insufficient_data` is an explicit non-prediction result with minimum-history guidance; never fabricate a confident forecast. Deterministic reorder calculations remain distinct from trained probabilistic forecasts. Model registry/version ownership resides in Python, business acceptance/persistence in Go.

The assistant does not approve orders, finalize payments or mutate stock. POS works during AI outages. No ML libraries, job workers or database connection are installed in the AI service.
