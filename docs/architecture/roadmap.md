# Incremental delivery roadmap

Phase 4 purchasing/shelves is implemented in the working tree and awaiting local acceptance; Phase 5+ remains planned. Phase 1A, Phase 1B, Phase 1C and Phase 2 passed their local acceptance gates on 2026-10-09; Phase 3 verification finished on 2026-10-10 after work began on October 9. Phase exits depend on actual verification evidence, not file existence or production-readiness assumptions. Phase 3.1–3.7 remains COMPLETED (Local); current Phase 4 checks and blockers are recorded in [Phase 4 progress](../development/phase4-verification.md).

## Phase 3 gates (2026-10-10)

- Phase 3.1 Terminal, 3.2 Carts/Holds, 3.3 Payments, 3.4 Sales/Inventory, 3.5 Receipts/History, 3.6 Registers/Shifts and 3.7 Integration/Security/QA: **COMPLETED (Local)**. 197 real POS API assertions, Go vet/race/build, 64 frontend tests, additive contracts, fresh migration validation and 17 browser regressions passed. Ten operational routes preserve the 16-module/106-route inventory.
- Cash and explicit manual QR/transfer acknowledgement are supported; payment gateways, split payments, discounts/separate tax, refunds/voids, sales dashboard and hardware/load validation are not claimed.
- Phase 3 overall: **COMPLETED (Local)**, not production readiness. See [Thai verification report](../development/phase3-verification.md).
- Phase 4: **IMPLEMENTED; LOCAL ACCEPTANCE PENDING**. Supplier/purchasing/shelf code and tests are present. Host checks pass, but current database/integration/browser acceptance is blocked by Docker availability and Go race checks by disabled cgo. Replenishment requires explicit human actions, not automatic purchasing or AI approval. See [current evidence and remaining gates](../development/phase4-verification.md).
