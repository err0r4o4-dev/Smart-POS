# Incremental delivery roadmap

Business phases below remain planned beyond Phase 1A identity. Phase 1A implementation is present but full runtime verification is pending; Phase 1B organization/branch membership and RBAC have not started. Phase 0 exit depends on actual verification evidence, not file existence.

| Phase                  | Goals and deliverables                                                                                                                                 | Dependencies                                      | Acceptance/tests/exit gate                                                                                                                                                                                                                                                | Risks                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 0 Foundation           | Monorepo, architecture, 16 module specs, 106-route inventory, three layouts, real health, minimal DB migration, FastAPI, Compose, CI                   | Local toolchains or Docker                        | Web lint/types/tests/build; Go format/vet/race/build; Python lint/tests/import; SQL constraints/RLS and migration rerun; gateway and responsive browser checks. No fabricated features. Record blocked checks.                                                            | Runtime availability, configuration drift, privileged development DB user |
| 1 Identity & Catalog   | Sessions, organizations, branches, staff roles, products/categories/units/barcodes/import; store settings                                              | Phase 0, approved session/tenant contracts        | Real session lifecycle, CSRF/Origin validation, Argon2id, rate limits, non-owner DB role, cross-tenant/branch denial, barcode uniqueness/unknown handling, import validation and UI integration. Exit: secure onboarding and accurate catalog.                            | Privilege escalation, last owner removal, import errors                   |
| 2 Inventory Core       | Locations, balances, append-only movements, adjustments, counts, transfers, reorder points, valuation                                                  | Identity and catalog                              | Ledger/balance reconciliation, exact fractional units, atomic transfer conservation, deterministic locking, retries, simultaneous oversell tests and authorization. Exit: reliable audited branch inventory.                                                              | Deadlocks, silent stock corruption, rounding                              |
| 3 POS & Sales          | Terminal/cart/holds, cash checkout, payment state, sales snapshots, stock deduction, receipts, register shifts; basic dashboard                        | Phases 1-2 and exact-money policy                 | Critical request idempotency, duplicate callback denial, no stock deduction before confirmed valid payment state, concurrent checkout, receipt reconciliation, keyboard/touch E2E. Exit: real cash sale lifecycle with reconciled stock and cash.                         | Overselling, duplicate sales, cash imbalance                              |
| 4 Purchasing & Shelves | Suppliers, draft/approved purchase orders, partial receiving, warehouse/shelf slots, replenishment/counts, deterministic suggestions                   | Phases 1-3 and inventory application ports        | Receive/ledger atomically, reject over-receipt/duplicate receive, transfer conservation, variance reconciliation; physical-vs-recorded shelf clarity. Exit: full purchase-to-shelf cycle.                                                                                 | Partial receipt state, unverified physical counts                         |
| 5 Business Operations  | Refunds/returns/exchanges, pricing/promotion rules and approvals, customers/groups/loyalty, batches/FEFO/expiry/quarantine/recalls/write-offs          | Phases 1-4                                        | Authorized state transitions, no excess refund, exact totals/rounding, promotion precedence, loyalty reversal/retry, no quarantined sale, retention requirements. Exit: audited exception flows and quality controls.                                                     | Fraud, PII exposure, conflicting promotion rules                          |
| 6 AI Intelligence      | Typed bounded Go -> AI contracts, versioned forecasts/reorder/shelf/anomaly proposals with explanations; report/read-model integration                 | Stable historical data and authorized read models | Insufficient-data responses, deterministic baseline vs trained model separation, timestamp/model/version/provenance, output validation, timeout/outage isolation, no automatic stock/payment/PO approval. Exit: explainable advisory intelligence with measured accuracy. | Data sparsity, leakage, drift, unjustified confidence                     |
| 7 Production Readiness | Security/performance review, backup AND restore drills, monitoring, durable jobs/outbox, alerting, accessibility, integrations and deployment/runbooks | All released feature gates                        | Load/concurrency and end-to-end reconciliation; production roles/secrets/TLS/cookies; restore to isolated environment; WCAG/responsive review; observability and rollback drill. Exit: explicit owner-approved release, never automatic from Phase 0.                     | Operational loss, hardening gaps, external payment/hardware failures      |

Each phase needs contract/migration review, focused tests, wider regression checks, documented ownership and explicit exit evidence. Do not automatically start Phase 1 after foundation delivery.
